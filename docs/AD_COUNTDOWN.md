# Ad countdown integration

Status: the countdown is attached to both playback wrappers through a scene-owned metadata Task. Local regressions and a controlled native countdown/pause/cleanup test pass. A naturally occurring Twitch ad and TV readability remain acceptance gates; the controlled native cue was synthetic.

The badge shows the remaining time of the current ad, with its position in the pod when the source provides a count and position. It never guesses the duration of an entire ad pod. It stays inside the current video area, including beside chat, and does not take remote focus or control playback.

`twitchAdCountdownRanges` accepts bounded, observed Twitch stitched-ad DATERANGEs and retains only five numeric fields per cue: start, end, duration, pod count and pod position. Session identifiers, signed URLs and tracking attributes are not retained. Other metadata classes do not become ads. Duplicate cues are collapsed; conflicting intervals are rejected conservatively.

The `AdCountdown` component exports `beginContent`, `setCues`, `updatePresented`, `clear` and `onDestroy`. The host supplies a local current-content owner, the sanitized cue array, localized labels and the video-area width. It must pass UTC microseconds from the actual presented media, including the frozen frame during pause or buffering. Invalid/missing clocks, terminal states, stale owners and disposal hide the badge. The component has no clock extrapolation, network task or timer.

The Roku-only LIVE Session explicitly enables observational program-date and ad-cue projection for a validated version-one playback descriptor. The underlying server keeps its disabled default for other callers. Projection preserves source epoch and presentation-time anchors without changing media selection or conversion. A separate bounded metadata Task reads the selected direct child playlist or the current loopback video playlist; an ambiguous Automatic ladder or unsupported proxy path cannot supply timing authority. The adapter accepts an exact native epoch-one presentation clock only inside corroborated source bounds. Relative player position or the current wall clock never substitutes for that mapping.

The scene owns one active metadata worker and one pending content replacement. Closing a worker requires both its safe closed response and actual stopped state before another starts. Content replacement, errors, stale owners, missing timing and disposal clear the badge. Main exit waits for both playback and metadata owners; blocked cleanup does not permit another worker. The metadata Task polls within finite transfer and file limits, deletes its own temporary file, and waits for an asynchronous destination to exist before inspecting its size and type. It never sends ad-tracking callbacks or skips media.

Portable regressions execute the actual BrightScript parser and SceneGraph component, including rendered labels, fractional countdowns, cue numbering, bounded layout, ownership, pause/buffer inputs and permanent disposal. Genuine normally exiting mutations and child timeout/output/crash controls are rejected. These checks establish the stated component contracts, not native ad delivery or a working TV countdown.
